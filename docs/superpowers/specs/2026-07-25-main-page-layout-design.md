# 주요 페이지 공통 레이아웃 설계

## 목표

하단 내비게이션으로 이동하는 매칭, 채팅, 마이 페이지의 화면 너비와 헤더 기준선을 통일한다. 페이지를 전환할 때 제목이 같은 위치에 표시되고, 본문도 같은 가로 영역을 사용하게 한다.

## 공통 레이아웃

`src/layout/MainPageLayout.jsx`를 추가해 다음 규격을 한 곳에서 관리한다.

- 전체 너비: `w-full`
- 최대 너비: `max-w-[600px]`
- 가운데 정렬: `mx-auto`
- 최소 높이: `min-h-[calc(100dvh-96px)]`
- 가로 잘림 방지: `min-w-0`
- 좌우 패딩: `px-5`
- 상단 패딩: `pt-[clamp(1rem,4vw,2rem)]`
- 기본 하단 패딩: 하단 내비게이션과 겹치지 않는 공통값

컴포넌트는 `title`, 선택적인 `description`, 선택적인 `headerAction`, `children`, 추가 클래스 이름을 받는다. 제목·부제·우측 액션을 공통 `header` 안에서 렌더링하고 각 페이지의 고유 콘텐츠는 `children`으로 렌더링한다.

## 헤더

- 제목은 세 페이지에서 같은 글꼴, 크기, 굵기, 행간을 사용한다.
- 부제는 동일한 위쪽 간격과 글자 스타일을 사용한다.
- 부제가 없는 마이 페이지도 제목의 위쪽과 왼쪽 기준선은 다른 페이지와 동일하다.
- 매칭 페이지의 실행 버튼은 `headerAction`에 전달해 기존 우측 배치를 유지한다.
- 동적 매칭 안내 문구와 오류 문구는 `description` 영역에 전달하며 기존 말줄임 및 오류 스타일을 유지한다.

## 페이지 적용

- `Matching`: 기존 최상위 `section`과 `header`를 공통 레이아웃으로 교체한다. 카드 영역에 필요한 넓은 하단 여백과 내부 간격은 페이지 전용 클래스로 유지한다.
- `Chat`: 기존 최상위 `section`과 `header`를 교체한다. 채팅 목록의 `mt-3`과 상태별 콘텐츠는 유지한다.
- `MyPage`: 기존 최상위 `section`과 `header`를 교체한다. 프로필 카드 이하의 간격과 최대 너비 제한은 제거해 공통 `600px` 본문 폭을 사용한다.

`MainLayout`과 하단 `NavigationBar`는 변경하지 않는다. 채팅방 상세 화면도 이번 공통화 대상에 포함하지 않는다.

## 기존 변경 보존

`Chat.jsx`에 존재하는 커밋되지 않은 상단 패딩 변경은 공통 레이아웃 규격에 흡수하되, 그 의도인 반응형 상단 여백을 그대로 유지한다. 다른 사용자 변경은 수정하거나 되돌리지 않는다.

## 검증

- 세 페이지가 모두 `MainPageLayout`을 사용하는지 회귀 테스트로 확인한다.
- 공통 레이아웃의 최대 너비, 좌우 패딩, 상단 패딩과 헤더 스타일을 확인한다.
- 매칭 페이지의 우측 실행 버튼과 동적 부제 스타일이 유지되는지 확인한다.
- 전체 테스트, 변경 파일 lint, 프로덕션 빌드를 실행한다.
