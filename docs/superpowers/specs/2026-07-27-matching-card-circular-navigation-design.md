# 매칭 카드 양방향 순환 탐색 설계

## 목표

매칭 카드의 탐색과 매칭 의사 결정 동작을 분리한다. 사용자가 직접 카드를 스와이프할 때는 양방향 원형 큐처럼 탐색하고, X와 하트 버튼은 각각 거절과 좋아요 상태 변경만 담당한다.

## 탐색 동작

- 왼쪽 스와이프는 현재 카드의 오른쪽 이웃을 표시한다.
- 오른쪽 스와이프는 현재 카드의 왼쪽 이웃을 표시한다.
- 첫 카드에서 오른쪽으로 넘기면 마지막 카드가, 마지막 카드에서 왼쪽으로 넘기면 첫 카드가 표시된다.
- 카드가 한 장뿐이면 스와이프해도 카드 전환 애니메이션을 실행하지 않는다.
- 카드 탐색은 서버에 매칭 요청을 보내지 않는다.

현재 사용자 ID를 기준으로 활성 카드를 추적하고, `people`이 새로 전달되면 가능한 경우 같은 사용자를 계속 표시한다. 해당 사용자가 사라졌다면 유효한 인접 인덱스로 보정한다.

## X 버튼 동작

사용자가 거절 확인을 완료하면 `REJECT` 요청을 전송한다. 성공한 경우 현재 카드는 약 240ms 동안 위쪽으로 이동하면서 투명도가 0으로 낮아진다. 애니메이션 완료 후 해당 사용자 ID를 현재 카드 큐에서 제외하고 다음 유효 카드를 표시한 다음 서버 상태를 새로고침한다.

서버 갱신 결과에 거절한 사용자가 포함되어도 같은 화면 세션에서는 다시 카드 큐에 넣지 않는다. 요청이 실패하면 카드와 인덱스를 유지하고 오류를 표시한다.

## 하트 버튼 동작

사용자가 좋아요 확인을 완료하면 `HEART` 요청을 전송하고 서버 상태를 새로고침한다. 카드 퇴장 애니메이션이나 탐색 인덱스 변경은 실행하지 않는다. 새 데이터에 현재 사용자가 남아 있으면 같은 카드를 유지하고 갱신된 상태를 표시한다.

## 상태 구조

- 원본 `people`: 부모가 제공하는 서버 상태
- 제외된 사용자 ID 집합: 이번 화면 세션에서 X 처리에 성공한 카드
- 표시 대상 목록: 원본 목록에서 제외된 사용자들을 제거한 결과
- 현재 인덱스: 표시 대상 목록 안의 활성 카드 위치
- 퇴장 상태: 스와이프의 좌우 방향 또는 X 처리의 위쪽 페이드 애니메이션

인덱스 계산은 작은 순수 함수로 분리해 음수와 배열 끝 순환을 명확하게 테스트한다.

## 오류 및 경계 조건

- 빈 목록이면 기존 빈 상태 UI를 유지한다.
- X 처리로 마지막 카드가 제외되면 카드 스택은 비어 있게 된다.
- API 요청 중에는 중복 버튼 요청과 카드 전환을 막는다.
- 상태 새로고침만 실패한 경우 서버 요청 성공 사실은 유지하고 오류 안내를 표시한다.
- 데이터 갱신으로 목록 길이가 줄어들면 현재 인덱스를 유효 범위로 보정한다.

## 테스트

- 왼쪽 이동이 다음 인덱스로 순환하는지 검증한다.
- 오른쪽 이동이 이전 인덱스로 순환하는지 검증한다.
- 빈 목록과 한 장 목록의 인덱스 동작을 검증한다.
- X 성공 후 사용자 제외 및 위쪽 페이드 퇴장 상태를 검증한다.
- 하트 성공 후 활성 카드가 바뀌지 않는지 검증한다.
- API 실패 시 카드가 제외되거나 이동하지 않는지 검증한다.

## 범위 제외

- 카드 레이아웃과 카드 콘텐츠 디자인 변경
- 채팅 버튼 동작 변경
- 서버 API 계약 변경
- 페이지를 벗어난 뒤에도 거절 카드 제외 상태를 영구 보존하는 기능
